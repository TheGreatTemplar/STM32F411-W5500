# STM32F411 + W5500

**Ethernet-контроллер для лабораторных стендов и радиоаппаратуры.**

Black Pill на STM32F411CEU6 и Ethernet-модуль W5500 образуют автономный стенд
с локальным веб-интерфейсом: измерение АЦП, управление LED и обмен с внешним
устройством по SPI2 или аппаратной I2C1. Разводка стенда независима от проекта TRX.

> **Сейчас:** проект Keil поддерживает четыре HTTP-соединения, два канала АЦП,
> LED, диагностику W5500 и консоли SPI2 / I2C1. Базовый ADC/LED проверен пользователем
> на железе; многоклиентность, SPI2 и I2C1 прошли программные проверки.

## Тест АЦП через браузер

Открой `adc_web_f411.uvprojx`, собери и загрузи прошивку через SWD.
После подключения Ethernet открой **[http://172.16.236.220:5025/](http://172.16.236.220:5025/)**.
Коды 12-битного АЦП и напряжения PA0/PA1 находятся в окне **Диагностика STM32F411**
и обновляются раз в 250 мс.
Заголовок страницы — **Монитор STM32F411**. Переключатель **Eng / Рус / 日本語** меняет
язык подписей, сообщений и диагностики без перезагрузки. Выбор сохраняется в
браузере; команды, настройки SPI и очередь передач при переключении не меняются.
Флаги, изображения и внешние языковые ресурсы не используются.
Под кнопкой W5500 находится **Диагностика STM32F411**. В этом отдельном окне
находятся **ВКЛ** / **ВЫКЛ** синего светодиода PC13, его текущее состояние,
два канала АЦП и статус внешней Flash. После сброса светодиод выключен; сетевой опрос его не переключает.
Кнопка **Диагностика W5500** открывает отдельное окно с параметрами W5500,
таблицей сокетов и счётчиками драйвера. Обновление снимка — по кнопке.
См. [описание диагностики и ограничений подключений](documentation/DIAGNOSTICS.md).

Панель адреса, uptime, числа измерений и опорного напряжения находится над часами.
Состояние шины и очередь — под переключателем SPI/I2C, счётчик наборов —
под кнопками загрузки/сохранения/удаления. Статус W25Q64JV перенесён в диагностику:
«запись №» означает внутреннюю ревизию сохранённых данных, а не версию прошивки.

**Часы RTC / LSE:** дата и время микроконтроллера, ручная установка произвольной
даты 2000–2099 и отдельная кнопка синхронизации с местным временем компьютера.
Автоматической синхронизации нет. Для сохранения хода при выключенном питании
нужен VBAT. [Описание часов и API](documentation/RTC.md).
[Предлагаемая калибровка хода](documentation/RTC_CALIBRATION.md) — через CALR;
калибровочный интерфейс пока не реализован.

**SPI-консоль:** PB13=SCK, PB14=MISO, PB15=MOSI, PB12=CS. На странице выбираются
режим 0–3, частота 62,5 кГц–25 МГц, MSB/LSB, полярность CS и HEX/ASCII.
Четыре команды до 256 байт каждая, у каждой свои TX/RX и кнопка передачи.
W25Q64JV (8 Мбайт, CS PA4, общая SPI1) содержит два банка по 64 именованных
набора: SPI — 0x780000…0x7FFFFF, I2C — 0x700000…0x77FFFF. По 512 Кбайт
на банк, две копии с CRC32 на набор; остальные 7 Мбайт не изменяются.
Имя — до 32 Unicode-символов. Старые I2C-наборы переносятся с проверкой копии;
каталог показывает только выбранную шину, одинаковые имена между банками допустимы.
Режим SPI, MSB/LSB и полярность CS применяются сразу после изменения без TX.
Частота выбирается для следующей передачи; idle SCK соответствует CPOL.
[Формат команд и проверка loopback](documentation/SPI_CONSOLE.md).

Передача SPI2 выполняется аппаратно через DMA1: Stream 3 RX и Stream 4 TX,
channel 0, 8-битные данные, пакеты 1…256 байт. CS удерживается до окончания
последнего бита; тайм-аут контролируется счётчиком тактов DWT.

**I2C-консоль:** переключатель **SPI / I2C** показывает одну шину. I2C1:
**PB8=SCL, PB9=SDA**, внешние подтяжки к 3,3 В. Адрес 7 бит (HEX 08…77),
запись, чтение или запись → повторный START → чтение. До 256 байт TX/RX,
100 кГц / Fast mode (фактически около 381 кГц при APB1 16 МГц).
Четыре команды, HEX/ASCII, TX/RX, очередь и библиотека работают для обеих шин.
Черновики шин независимы; старые Flash-наборы читаются как SPI.
[Подключение, примеры и API I2C](documentation/I2C_CONSOLE.md).

[Библиотека наборов](documentation/COMMAND_LIBRARY_DESIGN.md): загрузка,
сохранение, переименование и удаление; прежний снимок доступен как Default.
Справа от SPI / I2C — три узкие кнопки «Загрузить», «Сохранить», «Удалить».
Загрузка показывает только выбор набора и загрузку; сохранение — имя,
«Сохранить» и «Сохранить как». Удаление — жёлтое окно с дополнительным
подтверждением по имени. Размеры кнопок и окон постоянны на всех трёх языках.
Для следующего расширения предложены [варианты циклической передачи
в миллисекундах](documentation/CYCLIC_SPI_DESIGN.md) с проверкой времени обмена.
Автоматический цикл в текущей прошивке ещё не запускается.

| Параметр | Значение |
| --- | --- |
| IP | 172.16.236.220 |
| Маска | 255.255.255.0 |
| Шлюз | 172.16.236.1 |
| TCP / HTTP порт | 5025 |
| DHCP | Отключён, код DHCP отсутствует |
| JSON API | `GET /api/adc` |

Входы: **PA0 = ADC1_IN0**, **PA1 = ADC1_IN1**. Сигнал — 0…VDDA,
номинально 0…3,3 В, общая земля с источником обязательна. Кнопка KEY платы
связана с PA0. Расчёт вольт использует `APP_ADC_VREF_MV` в `src/config.h`.

Порядок подключения, сборки и настройки ST-Link — в [инструкции](firmware/README.md).

## Подключение W5500

| W5500 | STM32F411 | Примечание |
| --- | --- | --- |
| SCK | PA5 | SPI1 для W5500 |
| MISO | PA6 | SPI1 MISO |
| MOSI | PA7 | SPI1 MOSI |
| CS / SCSn | PA15 | Отдельный выбор Ethernet |
| RSTn | PB2 | GPIO после старта; учитывать BOOT1 при загрузке |
| INTn | Не подключён | Опрос в первой реализации |
| GND | GND | Общая земля |
| VCC | По схеме модуля | Проверить регулятор и допустимое питание модуля |

PA2 сохраняется как аналоговый резерв. Внешнее устройство подключается к отдельной
SPI2 на PB12–PB15. Полная карта — в [PINOUT.md](firmware/PINOUT.md).

PC14/PC15 выделены под кварц LSE 32.768 кГц. При штатной загрузке из Flash
BOOT0 должен быть LOW; для ROM-загрузчика также требуется LOW на PB2/BOOT1.

## Структура репозитория

Организация согласована с FLyEl-TRX.

| Каталог | Содержимое |
| --- | --- |
| `src/` | C99/CMSIS: плата, W5500, HTTP и HTML-страница |
| `firmware/` | Распиновка, сборка и отладка |
| `hardware/` | Схемы, платы, подключения и BOM |
| `documentation/` | Архитектура, протоколы и описание работы |
| `scripts/` | Сборка ArmClang, встраивание HTML и запуск проверок |
| `tests/` | Выполнение ARM-кода парсера и макетов HTTP/W5500 |
| `measurements/` | Измерения и результаты испытаний |
| `mechanical/` | Корпус, крепления и 3D-модели |
| `tooling/` | Оснастка и вспомогательные приспособления |
| `third_party/` | CMSIS Core и заголовки устройства ST с лицензиями |

Проект Keil — `adc_web_f411.uvprojx`. Сценарий `scripts/build.ps1` создаёт
`build/adc_web.axf`, `.hex` и `.bin`; µVision создаёт AXF/HEX в `Objects/`.
