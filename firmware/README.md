# Прошивка

Целевая среда: Keil µVision 5.38, Arm Compiler 6.19 (ArmClang).
Язык — C99, периферия — CMSIS и регистры STM32F411. Ассемблер допускается
для старта и участков, где он оправдан. HAL и Arduino не используются.

## Тестовый проект ADC Web

Открыть `adc_web_f411.uvprojx` в корне. Target — `ADC_Web_F411`.
Исходники и CMSIS-заголовки включены в репозиторий, сборка не требует HAL,
Arduino, сетевого middleware или установки Device Family Pack.
Собрать командой **Rebuild all target files**.

Для загрузки и просмотра регистров установить через Pack Installer официальный
`Keil::STM32F4xx_DFP`, выбрать `STM32F411CEUx` в Options for Target → Device.
В Debug выбрать **ST-Link Debugger**, Settings → Port: **SW**.
В Utilities использовать тот же отладчик; в Flash Download добавить алгоритм
для STM32F411, Flash 512 Кбайт с началом `0x08000000`. Конфигурация отладчика
зависит от установленного DFP и не проверялась без подключённого ST-Link.
Не добавлять сгенерированный pack startup/SystemInit: они уже есть в `src/`.

Подключение SWD: PA13/SWDIO, PA14/SWCLK, GND и опорное питание 3.3 В;
NRST — при необходимости. В штатном режиме BOOT0=0.

### Сборка из PowerShell

```powershell
.\scripts\build.ps1
```

Путь к ArmClang по умолчанию: `C:\Keil_v5_ARM\ARM\ARMCLANG\Bin`.
Для другой установки использовать `-Toolchain 'путь\ARMCLANG\Bin'`.
Результат — `build/adc_web.axf`, `build/adc_web.hex`, `build/adc_web.bin`.
HEX содержит адреса; BIN загружается с адреса `0x08000000`.

### Ethernet и браузер

Подключить W5500 по [распиновке](PINOUT.md), проверить питание и общий GND.
IP `172.16.236.220`, маска `255.255.255.0`, шлюз `172.16.236.1`, TCP-порт `5025`.
DHCP и DNS не используются. Компьютер должен иметь маршрут до этой подсети;
при прямом соединении можно назначить ему свободный адрес `172.16.236.x/24`.
Не назначать компьютеру `.220` или адрес шлюза `.1`.

Открыть **http://172.16.236.220:5025/** именно по HTTP.
JSON доступен по `http://172.16.236.220:5025/api/adc`.
Окно **Диагностика** читает `GET /api/diagnostics` при открытии и по кнопке
«Обновить». Доступные поля и ограничения — в [описании](../documentation/DIAGNOSTICS.md).
После адреса страница показывает текущую скорость Ethernet W5500: 10 или 100 Мбит/с.
Скорость берётся из статуса PHYCFGR, обновляется вместе с показаниями и скрывается
при потере связи. Это скорость физического линка до непосредственно подключённого
сетевого порта (компьютера или коммутатора).
Номер порта выбран для HTTP по заданию; это не SCPI-сервер.

### Измерения и индикация

- PA0 / ADC1_IN0 и PA1 / ADC1_IN1, 12 бит, коды 0…4095.
- Плановый период измерения — 20 мс; обслуживание TCP может увеличить интервал.
- Браузер опрашивает API через 250 мс после завершения предыдущего запроса.
- Вольты рассчитываются по номинальному VDDA=3300 мВ. Для точности измерить VDDA
  и изменить `APP_ADC_VREF_MV` в `src/config.h`; автокалибровки VDDA пока нет.
- Подавать только 0…VDDA относительно общего GND. На PA0 влияет кнопка KEY.
- Для проверки удобно подключить движки двух потенциометров 10 кОм к PA0/PA1,
  а крайние выводы — к 3.3 В и GND. Входы без источника могут показывать шум.
- Синий светодиод PC13 управляется кнопками **ВКЛ / ВЫКЛ** на странице.
  После сброса он выключен. Состояние сохраняется при обрыве Ethernet и
  повторной инициализации W5500; при сбросе MCU снова устанавливается «выключен».
  PC13 active-low: LOW включает светодиод, HIGH выключает.
  Автоматическая индикация сетевого статуса на PC13 заменена ручным управлением.

MCU работает от HSI 16 МГц, SPI1 — 1 МГц, ADC — 8 МГц с выборкой 480 тактов.
PC14/PC15 не конфигурируются и остаются для LSE. Сброс W5500 — PB2.
Отдельная SPI2: PB13 SCK, PB14 MISO, PB15 MOSI, PB12 программный CS.
Это автономный стенд, старые LCD/энкодер/74HC595 к PB12–PB15 не подключаются.
[Параметры SPI-консоли](../documentation/SPI_CONSOLE.md).

Сервер слушает порт 5025 на четырёх сокетах 0–3, каждый с 2 Кбайт RX и TX.
Ответы передаются пошагово, без ожидания TCP-подтверждения в блокирующем цикле.
Один зависший клиент не удерживает остальные сокеты. Команды управления у всех
клиентов общие; SPI-транзакции выполняются последовательно, до 100 мс на команду.

HTML хранится в `src/web/index.html`, встроенная копия — `src/web_page.h`.
После правки страницы выполнить `python scripts/embed_web.py` и пересобрать проект.
Встроенная копия включена в репозиторий: Python для обычной сборки не нужен.

## Выполненные проверки

Проект собран в µVision 5.38 / ArmClang 6.19 и сценарием PowerShell.
ARM-код парсера и макетов HTTP/W5500 выполнен через Unicorn; см. [tests](../tests/README.md).
Базовые ADC/LED и веб-интерфейс подтверждены пользователем на плате.
Четыре клиента и SPI2 проверены программными макетами и выполнением ARM-кода;
проверка их работы на реальных платах ещё требуется.

## Требования к реализации

- Явная настройка тактирования под фактическую ревизию Black Pill.
- SWD на PA13/PA14 сохраняется; PB3 не используется для SWO.
- Настройки SPI и выбор устройства выполняются на каждую транзакцию.
- SPI1 обслуживает W5500, SPI2 — отдельное устройство; доступа к SPI из IRQ нет.
- Ожидания периферии и сетевые запросы имеют тайм-ауты.
- Длина HTTP-запроса ограничивается, входные команды проверяются до выполнения.
- Аппаратные драйверы отделены от HTTP и логики конкретного устройства.
- Все блоки C оформляются в Allman, отступ — 4 пробела.

Лицензионные ключи Keil, локальные пути инструментов и настройки конкретного
отладчика в репозиторий не включаются.
