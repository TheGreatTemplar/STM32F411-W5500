# Проверки

ARM-код выполняется через Unicorn. Макеты заменяют аппаратный SPI/сокет;
они проверяют логику прошивки, а не электрические свойства настоящих плат.

Подготовка Python 3:

```text
python -m pip install unicorn==2.1.4 pyelftools==0.33
```

Запуск из корня проекта:

```powershell
.\scripts\test.ps1 -Python python
```

Проверяются:

- 1178 случаев HTTP-парсера: маршруты, методы, неверные версии, нулевые/управляющие
  байты, LED/SPI-заголовки, частичное тело SPI и переполнение Content-Length.
- W5500: IP/маска/шлюз, общий порт, память четырёх сокетов, LISTEN, оборачивание RX/TX
  и 16-битных указателей, нехватка TX-памяти, TIMEOUT, отсутствие SEND_OK,
  ошибка SPI и повторная инициализация.
- Диагностика W5500: чтение восьми сокетов, сетевых регистров, счётчиков
  передачи/тайм-аутов, сохранение IRQ-флагов и отсутствие записей в регистры
  при штатном снимке; сохранение программных счётчиков после сброса W5500.
- HTTP: побайтовая сборка заголовка, HTML/JSON, Content-Length, крайние значения
  ADC, ошибка измерения, ответы 404/405/431, неполный запрос, закрытие клиентом,
  ошибка отправки и возврат к LISTEN.
- LED: включение/выключение, отсутствие переключений при опросе АЦП и сбросе
  HTTP-состояния, запрет изменения по GET и некорректному POST, выполнение
  команды только после полного приёма заголовков.
- Четыре HTTP-клиента: раздельные ответы, неполный запрос, удержание SEND_OK
  одного клиента, прогресс остальных и сохранение уже поставленной в очередь выборки ADC.
- SPI2: 60 сочетаний режима/частоты, регистровая модель loopback, лимит 256 байт,
  HEX/ASCII, недопустимые параметры и числа; SPI1 при обмене SPI2 не изменяется.
- I2C1: строгий парсер, PB8/PB9 AF4 open-drain, чтение 1/2/3/4/16/256 байт,
  ACK/POS/STOP и repeated START, NACK адреса/данных, BUSY/LOW, BERR, тайм-аут,
  ARLO без STOP, сохранность SPI1/SPI2. HTTP: фрагментация и однократность.
- Flash v3: наборы I2C и пустые TX при чтении, перезапуск, совместимость v1/v2 SPI.
- PLL: выбор делителей, переключение и восстановление HSI/SysTick/ADC.
- W25Q64JV: 64 + 64 именованных набора SPI/I2C по четыре команды, границы секторов/страниц,
  перезапуск, прерванная запись/удаление, CRC и старая копия, миграция v1 в Default,
  полный каталог, повторное использование ID, переименование и дубликаты,
  UTF-8/32 символа, чужие данные в хвостах секторов и чужой JEDEC ID.
- API библиотеки: страницы каталога, фрагментированные load/delete/save,
  байтовая длина японского имени и отсутствие выполнения при лишних данных.
- Команда SPI поступает побайтово, исполняется только после полного тела
  и не повторяется при ожидании отправки ответа.
- API диагностики: восемь записей, предельные значения регистров,
  Content-Length и ответ 503 при недоступности данных.

Дополнительная проверка JavaScript страницы (Node.js, без npm-зависимостей):

```text
node tests/web_ui.cjs
```

Проверяет кнопки, последовательность POST/GET, отображение подтверждённого
состояния LED, отказ команды, восстановление связи и независимость от ошибки АЦП.
Также проверяет открытие/закрытие окна диагностики, вывод восьми сокетов,
ручное обновление, отсутствие параллельного запроса ADC и сообщение об устаревших данных.
SPI-проверка UI покрывает параметры запроса, вывод TX/RX, ошибки ввода,
неопределённый результат при обрыве сети и отсутствие автоматического повтора.
Также проверяются четыре независимых RX, загрузка общих настроек и четырёх
текстов из Flash, формат сохранения и ожидание завершения записи.
HEX-форматирование проверяется для вставки, позиции курсора внутри команды,
неполной пары, отклонения неверных символов/вставки целиком, 256 байт и сохранения
ASCII без изменений. Проверяются жёлтый класс ошибки, немедленное планирование
передачи, запуск команды после задержанного ADC без параллельных HTTP-запросов,
отсутствие повторов и показ измеренного времени CS/отклика. Регистровая модель
проверяет чтение DWT при разных частотах ядра; точность измерения проверяется на плате.
При задержанном ответе SPI проверяется FIFO: одна активная и четыре ожидающие
команды, отказ при заполнении, снимок текста на момент нажатия и по одному POST
на каждую принятую команду в исходном порядке.

Переключение RU/EN/JA: перевод ранее показанных и новых сообщений, возврат к
исходным русским строкам, заголовок документа, сохранение языка в localStorage,
неизменность текста команд и очереди, отсутствие HTTP-запросов от смены языка.
Библиотека UI: 32 японских символа, постраничный каталог, дубликат/длинное имя,
подтверждение замены правок, создание/загрузка/удаление без SPI-передачи.
В браузере проверены RU/EN/JA, сохранение смешанного имени «日本語 тест»,
загрузка Default и положение RTC рядом с заголовком. Координаты полей команды,
RX и следующей карточки до и после ошибки HEX совпали: сообщение не меняет
высоту заголовка и не сдвигает соседние окна.
Окна библиотеки разделены: загрузка показывает только выбор и загрузку;
сохранение — имя и две кнопки сохранения; удаление — выбор и удаление.
Проверяются фокус, скрытие чужих действий, жёлтый режим удаления,
дополнительное подтверждение с именем, отмена/Escape без запроса,
фиксация ID и отсутствие повторной операции при двойном подтверждении.
Три основные кнопки находятся справа от SPI/I2C в одной строке и имеют
постоянный размер. Размер окон операций — 680 × 292, подтверждения — 520 × 208;
на малом экране размеры ограничены viewport. Проверяются RU/EN/JA и ошибки.
В браузере проверены все три режима: видимые действия соответствуют окну,
координаты и размеры верхней строки совпадают для RU/EN/JA, все окна операций
имеют размер 680 × 292. Подтверждение показывает имя, жёлтый фон и фокус «Отмена».

RTC: 252 случая календаря, високосные годы, диапазоны времени, BCD и день недели,
две записи делителей, сохранение после сброса, работа с 2000 годом, ошибки LSE/INIT
и отказ сбрасывать чужой источник RTC. HTTP проверяет приём RTC-запроса по байту,
однократную установку и отсутствие записи при некорректном запросе. UI проверяет
ручной ввод, местное время ПК, отсутствие автоматической синхронизации/повтора,
ошибку LSE и сохранение набираемой даты. Ход и точность реального кварца макет не эмулирует.

UI I2C: независимые черновики и результаты SPI/I2C, запрет смены шины
при принятой передаче, адрес, пустые TX при чтении, NACK без повтора,
библиотека I2C и автоматический выбор шины набора, RU/EN/JA.
Модель не заменяет проверку уровней, фронтов и реального clock stretching.
В браузере проверены запись/чтение на HTTP-макете, сохранение I2C-набора,
возврат к черновику SPI и загрузка с выбором I2C. Размеры и координаты
проверенных полей совпали для RU/EN/JA; высота строки задана явно,
чтобы запасной японский шрифт не менял раскладку.

Дополнительно: независимое заполнение 64 мест обеих шин, одинаковые имена,
отказ записывать файл в чужой банк, перенос старых I2C-записей с прерыванием
до и после commit назначения; SPI-настройки без записи DR/активного CS,
занятость периферии, фрагментированный config-запрос и отказ принимать TX в нём.
UI: применение режима без «Передать», объединение быстрых изменений, ошибка
подтверждения без автоповтора, отдельные каталоги и окно STM32 с LED.
В браузере проверены режим SPI с подтверждением без TX/RX, отдельные списки
SPI/I2C, часы перед АЦП и работа LED в окне MCU. Окна памяти имеют одинаковую
высоту 292 и не прокручиваются внутри для RU/EN/JA; окно STM32 — 230.

Все перечисленные программные проверки пройдены. Электрические и сетевые
испытания реальных плат ведутся отдельно в [measurements](../measurements/).

SPI DMA: модель DMA1 Stream 3/4 проверяет channel 0, normal/direct mode,
8-битные размеры, MINC, RX > TX, адреса SRAM/DR, NDTR, RX-before-TX,
отсутствие CPU-доступа к DR и пакеты 1/11/256 байт. TX завершается раньше
RX и BSY; проверяются остановленный SysTick и переполнение DWT.
Ошибки: TE/DME/FE каждого потока, OVR/MODF, зависание DMA, недостающий RX,
зависший BSY и EN с аварийным reset DMA1. После каждой ошибки следующий
обмен проходит успешно. Это не измерение длительности пауз на плате.
