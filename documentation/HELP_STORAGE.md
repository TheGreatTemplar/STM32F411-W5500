# Справка во внешней Flash

Версия 0.4.0 добавляет GET /help и /help?lang=ru|en|ja, кнопку в шапке и
нативные title-подсказки RU/EN/JA. Справка открывается отдельной вкладкой;
основная консоль сохраняет свои черновики. При загрузке страницы без связи
статус на русском — «Нет связи», ошибка АЦП отдельно — «Сбой АЦП».

## Физическая область

W25Q64JV 8 МиБ: 0x6EE000…0x6FDFFF, всего 65536 байт, две банки по 32768 байт.
Сеть/RTC остаются в 0x6FE000…0x6FFFFF, I2C/SPI — на прежних адресах.
Неразмеченный остаток — 7266304 байта. Диагностика учитывает резерв справки.
Чужие непустые данные в новой области не стираются автоматически.

Банк начинается заголовком: magic HLP1, format=1, sequence, bytes, CRC32,
commit=0xA55AC33C. Архив начинается с +256. Длина ограничена 32512 байтами.
CRC32 относится к gzip-байтам. Размер заголовка 24 байта. Номер sequence
сравнивается с учётом переполнения uint32_t.

## Запуск и обновление

1. После сканирования каталога установщик получает исключительное кооперативное
   владение NOR через command_flash_claim(). Обмен SPI1 с W5500 не блокируется;
   блокируются другие операции с самой NOR. USART DMA/IRQ продолжаются.
2. Читаются оба заголовка, проверяется CRC целых записей. Пустой банк проверяется
   целиком. Понятная незавершённая запись может быть повторена; чужой формат
   и повреждённая подтверждённая запись не считаются пустыми.
3. Совпадение CRC и размера с текущим архивом означает чтение без перезаписи.
4. Для другой версии используется свободный/принадлежащий установщику банк,
   отличный от единственной целой копии. Сектора стираются по 4 КиБ, страницы
   программируются по 256 байт. На каждом обороте main выполняется небольшой шаг.
5. Заголовок и CRC payload считываются и проверяются. Commit записывается последним
   и проверяется. Только после этого новый банк становится активным.
6. При сбое сохраняется старая целая копия. После тайм-аута физической записи
   владение NOR не освобождается, пока WIP фактически не исчезнет. MCU reset при
   WIP обрабатывается общей инициализацией Flash.

Справка должна физически находиться во внешней Flash для HTTP-чтения. Внутренний
Flash содержит компактное gzip-семя для первого заполнения и восстановления.
Оно пока не удаляется из сборки: полностью вынести документ без такого резерва
можно будущим отдельным установщиком ресурсов/режимом сборки без семени.

## HTTP

HTML выдаётся с Content-Encoding: gzip, точной длиной и CSP, разрешающей встроенные
изображения. Передача выполняется кусками до 1024 байт из NOR в уже существующий
буфер клиента. Весь документ в RAM не копируется. Четыре клиента сохраняют свои
смещения. Занятость NOR записью набора приостанавливает чтение, а не выдаёт мусор;
сохраняются обычные HTTP-тайм-ауты. GET не пишет Flash.

Пока установка/сканирование не закончены, GET возвращает 503 с Retry-After и
Refresh=2; при неподдерживаемой/отсутствующей Flash или чужих данных автоматического
повтора нет. Без gzip — 406, POST /help — 405. Языки выбираются уже в документе,
одна gzip-копия содержит RU/EN/JA.

## Генерация и проверки

Исходник — documentation/help.html. Генератор scripts/embed_help.py создаёт
src/help_seed.h; файл входит в репозиторий и обычная сборка Keil не требует Python.

ARM/NOR-модель проверяет первое заполнение, чтение и распаковку, отсутствие
перезаписи, обновление другой банки, восемь остановок питания, частичный commit,
CRC-отказ, сохранность старой копии/чужих данных, границы, владение, отсутствие или
неподдерживаемую Flash и зависший WIP. HTTP-модель проверяет потоковое чтение,
возобновление после busy, gzip/503/405/CSP и совпадение документа. Это регистровые
и NOR-модели, не физический тест обрыва питания на плате.
