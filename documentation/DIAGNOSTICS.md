# Диагностика стенда

Кнопка **Диагностика** вверху основной страницы открывает отдельное окно.
При открытии и по нажатию **Обновить** выполняется `GET /api/diagnostics`.
Постоянного фонового опроса диагностики нет. Закрыть окно можно кнопкой или Escape.
В этом окне можно добавлять следующие диагностические блоки без расширения главного экрана.

## Из регистров W5500

| Данные | Источник |
| --- | --- |
| Версия чипа, ожидается 0x04 | VERSIONR |
| Link, скорость 10/100 Мбит/с, Full/Half duplex | PHYCFGR |
| IP, маска, шлюз, MAC | SIPR, SUBR, GAR, SHAR |
| Интервал и число повторов | RTR, RCR |
| Общие флаги и событие конфликта IP | IR |
| Режим работы и исходные значения PHY/IRQ | MR, PHYCFGR, IR |
| Состояния всех восьми сокетов | Sn_SR |
| Локальный порт и адрес/порт удалённого узла | Sn_PORT, Sn_DIPR, Sn_DPORT |
| Выделенная RX/TX память | Sn_RXBUF_SIZE, Sn_TXBUF_SIZE |
| Ожидающие чтения RX-байты и свободное место TX | Sn_RX_RSR, Sn_TX_FSR |
| Флаги сокетов | Sn_IR |

Снимок читает регистры последовательно, поэтому значения разных строк не обязаны
относиться к одному такту времени. Сам HTTP-запрос диагностики виден в socket 0.
Регистры IRQ при чтении не сбрасываются. Флаг конфликта IP означает, что чип
зафиксировал событие; это не непрерывная проверка уникальности адреса.

Скорость/дуплекс характеризуют физическое соединение W5500 с ближайшим сетевым
портом. При подключении через коммутатор это линк до коммутатора.
RTR/RCR — настройки повторов, а не счётчики фактически выполненных повторов.

## Счётчики прошивки

- Время работы MCU.
- Число попыток инициализации W5500.
- Ошибки обмена SPI, после которых драйвер требует повторной инициализации.
- Тайм-ауты отправки: флаг TIMEOUT или истечение программного ожидания.
- Байты, прочитанные приложением из TCP RX socket 0.
- Байты, передача которых завершилась SEND_OK.

Счётчики сохраняются при повторной инициализации W5500 и сбрасываются при старте MCU.
Это 32-битные значения с переходом через ноль при переполнении.
Они не включают весь служебный Ethernet-трафик и не являются числом пакетов,
ошибок CRC или ретрансляций. Последующие байты самого диагностического ответа
попадут только в следующий снимок.

У W5500 нет доступных в этой карте регистров датчиков температуры, питания или
качества кабеля в метрах. Для таких измерений нужны дополнительные источники.
В это же окно позднее можно добавить причину сброса MCU, состояние LSE/RTC,
оценку VDDA и температуру STM32 с учётом калибровки.

## Несколько компьютеров

У W5500 восемь независимых аппаратных сокетов и 32 Кбайт памяти буферов
(по 16 Кбайт для TX и RX). Число сокетов не равно числу компьютеров:
один браузер тоже может создавать несколько TCP-соединений.

Текущая прошивка выделяет память и обслуживает только socket 0: по 8 Кбайт RX/TX.
Она обрабатывает одно TCP-соединение за раз и после каждого ответа закрывает его.
Разные компьютеры могут получать ответы по очереди, но при одновременном опросе
возможны отказы соединений и сообщения «Нет свежих данных».
Надёжная одновременная работа нескольких браузеров в этой версии не заявляется.

Для этого нужно выделить несколько слушающих сокетов с одним локальным портом,
разнести состояние HTTP по соединениям и перераспределить буферы, например
по 2 Кбайт RX/TX на четыре сокета. Состояние управляемого устройства остаётся
общим: последняя принятая команда меняет его для всех клиентов.
