# Сетевые настройки и системная Flash

Кнопка «Сменить адрес» открывает отдельное окно IPv4, маски, шлюза и HTTP-порта.
DHCP не используется. Проверяются десятичные октеты 0…255, непрерывная маска
/1…/30, unicast IP, запрет network/broadcast адресов и порт 1…65535. Ненулевой
шлюз должен быть другим допустимым хостом той же подсети. 0.0.0.0 отключает шлюз.
Проверка не обнаруживает другой прибор с уже занятым IP: адрес выбирает оператор.

«Сохранить и применить» сначала записывает и проверяет Flash. Браузер опрашивает
состояние до подтверждённого commit и только затем отдельно разрешает переключение.
Через 2 секунды главный цикл переинициализирует W5500 с новыми параметрами,
сбрасывает HTTP-клиентов и слушает новый порт. Текущая вкладка остаётся на старом
адресе; для перехода дана ссылка на новый. ПК должен иметь маршрут в новую подсеть.
Автоматических повторов POST нет. При потере ответа состояние операции неизвестно:
проверить старый/новый адрес перед повторной записью. На следующем включении
используется последняя подтверждённая запись, даже если переключение ещё не было
запрошено до выключения питания.

## Отдельные системные сектора

Два сектора 0x6FE000 и 0x6FF000 (8192 байта) расположены перед банками I2C/SPI.
Наборы остаются в 0x700000…0x7FFFFF, 64 места каждой шины. Геометрия набора
не меняется. Системная запись 44 байта: magic SYS1, version, sequence, payload_size,
CRC32, commit (по 4 байта), IPv4/маска/шлюз (по 4 байта), порт uint32 и поправка
RTC int32 в шагах smooth calibration. CRC исключает собственное поле и commit.
Запись в другую копию: erase, program, verify, commit последним, чтение commit.
Старая копия сохраняется до успеха. Чужая область не стирается; незавершённая
запись известного системного формата может быть повторно использована.

Чтение обеих копий выполняется до запуска Ethernet. Без сохранённой конфигурации
используются 172.16.236.220 / 255.255.255.0, шлюз 172.16.236.1, порт 5025.
При повреждении новой копии выбирается предыдущая валидная. Отсутствие/ошибка
Flash оставляет заводскую сеть; калибровка RTC при недоступной системной области
автоматически не перезаписывается. Сброс системных параметров при недоступном
адресе требует SWD/внешнего программатора: найти действующий адрес в RAM либо
стереть только эти два системных сектора. Банки команд трогать не нужно.

## API

GET /api/settings: сохранённые ip, mask, gateway, port, calibration (−511…512 шагов),
sequence, busy, error; cal_pending, cal_applied, cal_error и active_port.
POST /api/settings сохраняет весь снимок. POST /api/settings/apply разрешает
переключение сети только для точного подтверждённого снимка. Оба POST требуют
X-Device-Control: 1 и точный Content-Length. Тело строго в таком порядке:

```text
ip=172.16.236.220
mask=255.255.255.0
gateway=172.16.236.1
port=5025
cal=0
seq=0
```

Последняя строка оканчивается LF. seq — прочитанное поколение; устаревшая запись
отклоняется. После commit оно увеличивается на 1; apply отправляет уже новое seq.
Flash-команды сериализованы с библиотекой. Пока назначено переключение сети,
новые сохранения/применения системных настроек отклоняются.
