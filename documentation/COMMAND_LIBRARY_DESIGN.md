# Проект библиотеки именованных наборов SPI

Статус: **предложенная схема следующего расширения**, ещё не реализованная
файловая библиотека. В текущей прошивке сохраняется один снимок четырёх команд
в последних 8 Кбайт W25Q64JV. Этот документ задаёт формат и поведение будущей библиотеки.

## Как это будет выглядеть

Над четырьмя полями команд — строка **Набор**, выпадающий список сохранённых имён,
поле имени с пределом 32 символа и кнопки:

- **Загрузить** — прочитать выбранный набор и заполнить четыре поля и настройки.
- **Сохранить** — обновить выбранный набор текущими четырьмя командами.
- **Сохранить как** — создать новый набор под введённым именем.
- **Удалить** — удалить выбранный набор из каталога.

Примеры: `RFIC03 — проверка`, `TRX — запуск`, `W5500 — регистры`.
Это плоский каталог: один «файл» соответствует одной четвёрке. Каталогов внутри
каталога, расширений файлов, FAT и сторонних библиотек для начала не требуется.

Загрузка только меняет рабочие поля. Она **не передаёт** команды по SPI,
не записывает Flash и не меняет уже принятые команды в очереди передачи.
При несохранённых правках UI явно показывает их наличие; загрузка не должна
молча затирать набираемые данные. Передача остаётся отдельной кнопкой у каждого поля.

## Имена и содержимое

Имя — 1…32 кодовые точки Unicode, латиница и кириллица поддерживаются.
В записи отводится до 128 байт UTF-8, а не 32 байта: русские буквы не сокращают
допустимую длину имени вдвое. Управляющие символы, NUL, `/`, `\\`, пустые имена,
`.` и `..` запрещены. Начальные/конечные обычные пробелы убираются.
Сравнение имён учитывает регистр; совпадающее имя при «Сохранить как» даёт ошибку.
Существующий набор обновляется кнопкой «Сохранить» по стабильному ID.
Язык интерфейса не меняет имена и данные пользователя.

Один набор содержит имя, четыре текста до 768 ASCII-символов каждый,
режим 0–3, частоту, порядок битов, полярность CS и HEX/ASCII.
Формат и настройки общие для четырёх команд, как сейчас. Пустые поля разрешены.
Принятый объём передачи каждого поля — до 256 байт. TX/RX в файл не входят.

## Размещение в W25Q64JV

Предлагается 64 набора по два сектора 4 Кбайт:

| Параметр | Значение |
| --- | --- |
| Размер библиотеки | 64 × 2 × 4096 = 524288 байт, 512 Кбайт |
| Диапазон | `0x780000…0x7FFFFF`, последние 6,25% Flash |
| Набор ID 0 | `0x780000…0x781FFF` |
| Набор ID 63 | `0x7FE000…0x7FFFFF`, область текущего снимка |
| Остальная память | 7,5 Мбайт для других задач |

В секторе помещается запись примерно 3,3 Кбайт: заголовок, имя UTF-8,
параметры, длины четырёх текстов и сами тексты. Изменяемый файл записывается
в неактивный сектор своей пары; другая целая копия сохраняется до конца записи.

Заголовок версии 2: magic, версия формата, ID/поколение, длины, признак живого
файла или удаления, CRC заголовка/имени, CRC всей записи и отдельное слово commit.
CRC заголовка позволяет быстро прочитать каталог без чтения всех полезных данных.
Перед загрузкой или передачей данных клиенту проверяется полная CRC и все границы.
Слово commit программируется последним, после проверки чтением.

Удаление тоже записывает новую версию с признаком удаления — tombstone.
Просто стереть одну копию недостаточно: после перезапуска тогда могла бы
восстановиться старая копия удалённого файла. Повторное использование слота
получает новое поколение и становится видимым только после commit.

Стирание/программирование остаётся кооперативным, страницами до 256 байт;
HTTP и RTC продолжают обслуживаться. Одновременно выполняется одна операция
записи библиотеки. Chip Erase и автоматическое снятие защиты не нужны.

Каталог на 64 коротких записи занимает ориентировочно 10 Кбайт RAM.
Полезные данные в RAM нужны только для выбранного набора и текущей операции записи.
Не требуется держать все 64 × 4 текста в оперативной памяти.

## Совместимость и защита данных

При обновлении текущий снимок версии 1 распознаётся в паре ID 63 и показывается
как `Default`. До явного сохранения пользователя его формат не изменяется.
Первая запись версии 2 использует вторую копию и не уничтожает целую старую запись
до подтверждённого commit. Нельзя форматировать всю Flash при обновлении прошивки.

Дополнительные сектора сначала читаются. Чужие данные не стираются автоматически;
занятые/неоднозначные слоты помечаются недоступными. При первом прерванном создании
файла ещё нет резервной копии; неоднозначную частичную запись нужно отличать от
чужих данных и при необходимости оставлять для сервисного восстановления.
Если свободных слотов нет, интерфейс сообщает об этом и ничего не перезаписывает.

Поколение записи, а не календарь RTC, определяет новую копию: стенд позволяет
ставить условное время, поэтому сортировка/восстановление по дате небезопасны.
После перезапуска рабочим по умолчанию можно выбирать последний успешно сохранённый
живой набор. Простое чтение другого набора не должно расходовать ресурс Flash.

## Предлагаемый API и проверки

- `GET /api/command-sets` — каталог: ID, имя, поколение, занятые/свободные слоты;
  при необходимости постранично по 8–16 записей.
- `GET /api/command-sets/<id>` — проверенный набор для заполнения рабочих полей.
- `POST /api/command-sets/save` — новый/изменённый снимок, имя UTF-8 и четыре текста.
- `POST /api/command-sets/delete` — явное удаление по ID.

Записывающие запросы требуют `X-Device-Control: 1` и точный Content-Length.
Сервер повторно проверяет UTF-8, длину имени в символах/байтах, уникальность,
параметры SPI и все четыре команды. Контроль имени только в браузере недостаточен.
Необходимо сохранить ограничение запроса 4096 байт либо явно увеличить его,
проверив худший размер вместе с HTTP-заголовками.

Перед реализацией нужны проверки: кириллица и 32 символа, неверный UTF-8,
совпадение имён, полный каталог, миграция версии 1, обрыв на каждой стадии записи,
удаление без восстановления старой копии, чужие сектора, параллельные браузеры,
отсутствие SPI-передачи при загрузке и сохранение снимков уже принятых команд в очереди.
