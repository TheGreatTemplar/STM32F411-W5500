# Библиотека именованных наборов SPI / I2C

Статус: **реализована**. Два независимых банка по 64 набора в W25Q64JV,
каждый содержит четыре команды и общие настройки SPI2 либо I2C1. Код C99/CMSIS,
без FAT, HAL и Arduino.

## Работа на странице

Справа от переключателя **SPI / I2C**, у правого края консоли, находятся
три узкие кнопки **Загрузить**, **Сохранить**, **Удалить**. Они всегда занимают
одну строку. На узком экране панель прокручивается по горизонтали вместо переноса.

- Окно загрузки: только список наборов и кнопка «Загрузить», фокус на списке.
- Окно сохранения: только имя и «Сохранить» / «Сохранить как», фокус на имени.
- Окно удаления: жёлтый фон, список и «Удалить». После выбора появляется
  дополнительное жёлтое окно с вопросом и точным именем набора; фокус на «Отмена».

До подтверждения запрос удаления не отправляется. Отмена или Escape ничего
не удаляют. Подтверждение фиксирует ID выбранного набора; двойное нажатие не
создаёт повторной операции. Имя в вопросе выводится как текст без перевода.
Окна операций имеют одинаковый размер 680 × 292, окно подтверждения — 520 × 208
(с ограничением по размеру экрана). Поля, кнопки и место для сообщений не меняют
размеров при смене языка или ошибке. Загрузка закрывает окно при успехе;
сохранение оставляет результат записи видимым. «Закрыть» и Escape закрывают окно.

- **Загрузить** в окне — прочитать выбранный набор в четыре поля и настройки.
- **Сохранить** — обновить загруженный набор; изменение имени переименовывает его.
- **Сохранить как** — создать новый набор под введённым именем.
- **Удалить** — удалить выбранный в списке набор после подтверждения.

Загрузка не запускает обмен по выбранной шине и не пишет Flash. При несохранённых
правках требуется подтверждение замены рабочих полей. Уже принятые в ручную
очередь команды сохраняют свои снимки. После включения загружается последний
успешно сохранённый живой набор. Фоновый опрос не заменяет набираемые тексты.
При начальном сканировании показан прогресс; операции записи пока недоступны.

Имя — 1…32 кодовые точки Unicode, до 128 байт UTF-8: русский и японский
поддерживаются. Запрещены управляющие символы, слеши, пустое имя, `.` и `..`.
Браузер убирает пробелы по краям; сервер отвергает крайние обычные пробелы.
Сравнение учитывает регистр; совпадающее имя другого набора той же шины — ошибка.
Между SPI и I2C одинаковые имена разрешены. В списке виден только банк текущей шины.
Язык интерфейса не переводит пользовательские имена и команды.

В наборе хранятся четыре текста до 768 ASCII-символов каждый (до 256 байт
передачи), выбранная шина и HEX/ASCII. Для SPI — частота, режим 0–3,
MSB/LSB и полярность CS; для I2C — частота, 7-битный адрес, операция и длина RX.
Пустые поля допустимы. Настройки общие для четырёх команд; TX/RX не сохраняются.

## Формат и размещение

| Параметр | Значение |
| --- | --- |
| Flash | W25Q64JV, 8 Мбайт, JEDEC EF4017 / EF7017 |
| Оба банка | 128 × 2 × 4096 = 1 Мбайт |
| SPI, ID 0…63 | `0x780000…0x7FFFFF`, прежние адреса сохранены |
| I2C, ID 64…127 | `0x700000…0x77FFFF` |
| Новый набор | ID 128 в запросе сохранения, свободный слот выбирается внутри банка |
| Остальная память | 7 Мбайт, библиотекой не изменяется |

Каждый ID имеет два сектора. Запись v4 занимает 3812 байт: первые 3284 байта
совпадают с v3; затем четыре uint32_t длины имён команд и четыре массива по
128 байт UTF-8 (до 32 Unicode-символов, пустое имя допустимо).
Историческая запись v3 занимает 3284 байта: первые 3268 байт
совпадают с v2 (прежний снимок v1, признак удаления, длина и 128 байт имени),
затем bus, address, operation и read_size, по uint32_t. Заголовок:
magic, версия, поколение, размер полезных данных, CRC32, commit. CRC охватывает
всю запись, кроме полей CRC/commit; отдельной CRC заголовка нет.
Поколение, а не произвольное время RTC, определяет новую копию.

Обновление стирает неактивный сектор, пишет страницы до 256 байт, проверяет
чтением и последним программирует commit. При прерывании обновления остаётся
предыдущая целая копия. Удаление записывает новое поколение с признаком удаления:
старая копия после перезапуска файл не восстанавливает. Удалённые слоты можно
использовать повторно. Одновременно выполняется одна операция записи.

При старте весь диапазон читается по 256 байт за вызов основного цикла.
Проверяется полная CRC и непустые хвосты секторов. Непустые пары без целой
известной записи блокируются; автоматического стирания и Chip Erase нет.
При одной целой копии её пара принадлежит набору и вторая может обновляться.
Первое прерванное создание ещё не имеет резервной копии: такой слот может
потребовать отдельного сервисного восстановления. Заполненный каталог даёт
ошибку, соседние наборы не перезаписываются. Защита Flash не снимается.

Старый снимок v1 распознаётся в ID 63 как **Default**. До явного сохранения
его формат не меняется; первая v4 пишется во вторую копию. Именованные
наборы v2 читаются как SPI; CRC проверяется по длине соответствующей версии. Обновление прошивки
не форматирует Flash. Каталог занимает около 18,5 Кбайт RAM; все 128 наборов текстов
в RAM не хранятся. Сканирование и ожидание записи кооперативные, HTTP/RTC работают.

## API

`GET /api/library` возвращает первые восемь физических слотов: `sets` (ID/имя),
`used`, `blocked`, `next`, `scanning`. Каждая запись `sets` содержит `bus`
(2=SPI2, 1=I2C1); интерфейс показывает эту шину перед именем. Следующая страница — `POST /api/library`
с телом `list 8\n`, далее смещение из `next` до `null`.

Операции `POST /api/library` требуют `X-Device-Control: 1` и точный
Content-Length. Запрос вместе с заголовками — не более 5120 байт.

- `load 63\n` — 200 и проверенный рабочий снимок.
- `delete 63\n` — 202, асинхронное удаление.
- `save <id> <байтовая длина имени UTF-8>\n`, затем имя и перевод строки,
  затем прежний формат снимка. ID 128 означает новый набор в банке, заданном строкой bus.

Пример создания (после последних данных перевода строки **нет**):

```text
save 128 6
日本
bus=2 mode=0 hz=20000000 lsb=0 cs_high=0 format=hex
lengths=5,2,0,5
9F 00AA01 02
```

Для I2C первая строка снимка имеет формат POST `/api/i2c`, например
`bus=1 hz=100000 addr=80 op=2 read=4 format=hex`. Далее та же строка `lengths`
и четыре текста; при op=1 все тексты пустые. Загрузка выбирает нужную консоль
без передачи. Несохранённый черновик другой шины проверяется перед заменой.
[Настройки I2C](I2C_CONSOLE.md).

При первом старте сканируются все 128 пар. Прежние живые I2C-файлы из ID 0…63
переносятся в ID 64…127: записать и проверить новую копию, затем подтвердить
удаление старой записи. После сброса прогресс восстанавливается по CRC,
поколению и имени: целая новая копия не дублируется, старая не удаляется до commit.
Копия сохраняет поколение исходного файла, чтобы перенос сам по себе не делал
старый набор последним сохранённым; отметка удаления получает новое поколение.
Во время переноса запись из браузера закрыта. Чужие/невалидные данные не стираются;
при невозможности безопасного переноса выводится ошибка, исходные записи сохраняются.
Обновление одного ID снимком другой шины отвергается. API-клиентам после обновления
нужно использовать новый ID создания 128; старый ID 64 теперь принадлежит I2C.

Длины четырёх текстов задают границы их конкатенации. Сервер проверяет UTF-8,
имя, уникальность, параметры SPI и команды перед началом записи.
202 означает принятие операции. Завершение: `GET /api/commands`,
`busy=false`, `save_ok=true`, `error=0`. Ответ также содержит `id`, `name`,
`scanning`, `scan`, состояние Flash, настройки и `commands`.
Прежний `POST /api/commands` обновляет текущий набор либо создаёт Default в ID 63.
При сетевом обрыве браузер не повторяет запись автоматически.

Браузеры имеют собственные рабочие поля. Запись явно адресуется по ID;
одновременная операция отвергается как busy. Последовательные обновления
одного ID из разных браузеров сохраняют последнюю успешно принятую версию.

## Проверки

ARM-макет: 64 SPI + 64 I2C и полные каталоги, UTF-8/32 символа, дубликаты,
переименование, миграция v1, CRC/резервная копия, прерывание записи и удаления,
повторное использование ID и чужие данные в хвосте сектора. HTTP: фрагментация,
байтовая длина японского имени, однократность выполнения. UI: создание,
выбор/удаление без передачи SPI2, сохранение ручной очереди и имён при смене языка.
Испытания реальной W25Q64JV с отключением питания выполняются отдельно.

## Индивидуальные имена команд (v4)

Четыре имени хранятся внутри набора вместе с четырьмя текстами и настройками.
Имя команды не является именем файла: разрешены пробелы, слеши и любая корректная
UTF-8 строка без управляющих символов, до 32 Unicode scalar values / 128 байт.
Пустые имена разрешены. Сохранение имени не передаёт команду устройству.
GET снимка возвращает дополнительный массив `command_names` из четырёх строк.

Старые записи v1/v2/v3 читаются с прежним размером и CRC; имена нормализуются
в пустые строки в RAM. Автоматической перезаписи записей ради имён нет.
При явном сохранении создаётся v4 в другой копии, с прежним commit-last и CRC.
Размер сектора, ID и квоты 64 SPI + 64 I2C не изменились. Прошивка старее v4
не обязана понимать новые записи: после обновления следует использовать новую версию.

HTTP-тело прежнего снимка может завершаться после текстов (тогда имена пустые).
Новый клиент добавляет после точно отмеренных текстов суффикс:

```text
<LF>names=6,16,9,0<LF>RFIC03Проверка日本語
```

Длины имён — в байтах UTF-8, не в UTF-16 единицах JavaScript. Далее идут имена
подряд без разделителей. Дополнительные байты, неправильная UTF-8, управляющие
символы и превышение лимита отклоняются до начала записи. Полный HTTP-запрос
ограничен 5120 байтами, JSON-ответ — 8192. Имя команды не входит в TX SPI/I2C.
