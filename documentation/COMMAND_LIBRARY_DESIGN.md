# Библиотека именованных наборов SPI

Статус: **реализована**. Плоский каталог на 64 набора в W25Q64JV,
каждый содержит четыре команды и общие настройки SPI2. Код C99/CMSIS,
без FAT, HAL и Arduino.

## Работа на странице

- **Загрузить** — прочитать выбранный набор в четыре поля и настройки.
- **Сохранить** — обновить загруженный набор; изменение имени переименовывает его.
- **Сохранить как** — создать новый набор под введённым именем.
- **Удалить** — удалить выбранный в списке набор после подтверждения.

Загрузка не передаёт команды по SPI2 и не пишет Flash. При несохранённых
правках требуется подтверждение замены рабочих полей. Уже принятые в ручную
очередь команды сохраняют свои снимки. После включения загружается последний
успешно сохранённый живой набор. Фоновый опрос не заменяет набираемые тексты.
При начальном сканировании показан прогресс; операции записи пока недоступны.

Имя — 1…32 кодовые точки Unicode, до 128 байт UTF-8: русский и японский
поддерживаются. Запрещены управляющие символы, слеши, пустое имя, `.` и `..`.
Браузер убирает пробелы по краям; сервер отвергает крайние обычные пробелы.
Сравнение учитывает регистр; совпадающее имя другого набора — ошибка.
Язык интерфейса не переводит пользовательские имена и команды.

В наборе хранятся четыре текста до 768 ASCII-символов каждый (до 256 байт
передачи), частота, режим 0–3, MSB/LSB, полярность CS и HEX/ASCII.
Пустые поля допустимы. Настройки общие для четырёх команд; TX/RX не сохраняются.

## Формат и размещение

| Параметр | Значение |
| --- | --- |
| Flash | W25Q64JV, 8 Мбайт, JEDEC EF4017 / EF7017 |
| Библиотека | 64 × 2 × 4096 = 512 Кбайт |
| Диапазон | `0x780000…0x7FFFFF` |
| ID 0 | `0x780000…0x781FFF` |
| ID 63 | `0x7FE000…0x7FFFFF`, прежняя область снимка |
| Остальная память | 7,5 Мбайт, библиотекой не изменяется |

Каждый ID имеет два сектора. Запись v2 занимает 3268 байт: прежние поля v1
и добавленные признак удаления, длина имени и 128 байт имени. Заголовок:
magic, версия, поколение, размер полезных данных, CRC32, commit. CRC охватывает
всю запись, кроме полей CRC/commit; отдельной CRC заголовка нет.
Поколение, а не произвольное время RTC, определяет новую копию.

Обновление стирает неактивный сектор, пишет страницы до 256 байт, проверяет
чтением и последним программирует commit. При прерывании обновления остаётся
предыдущая целая копия. Удаление записывает новое поколение с признаком удаления:
старая копия после перезапуска файл не восстанавливает. Удалённые слоты можно
использовать повторно. Одновременно выполняется одна операция записи.

При старте весь диапазон читается по 256 байт за вызов основного цикла.
Проверяется полная CRC и непустые хвосты секторов. Непустые пары без целой
известной записи блокируются; автоматического стирания и Chip Erase нет.
При одной целой копии её пара принадлежит набору и вторая может обновляться.
Первое прерванное создание ещё не имеет резервной копии: такой слот может
потребовать отдельного сервисного восстановления. Заполненный каталог даёт
ошибку, соседние наборы не перезаписываются. Защита Flash не снимается.

Старый снимок v1 распознаётся в ID 63 как **Default**. До явного сохранения
его формат не меняется; первая v2 пишется во вторую копию. Обновление прошивки
не форматирует Flash. Каталог занимает около 9 Кбайт RAM; все 64 набора текстов
в RAM не хранятся. Сканирование и ожидание записи кооперативные, HTTP/RTC работают.

## API

`GET /api/library` возвращает первые восемь физических слотов: `sets` (ID/имя),
`used`, `blocked`, `next`, `scanning`. Следующая страница — `POST /api/library`
с телом `list 8\n`, далее смещение из `next` до `null`.

Операции `POST /api/library` требуют `X-Device-Control: 1` и точный
Content-Length. Запрос вместе с заголовками — не более 4096 байт.

- `load 63\n` — 200 и проверенный рабочий снимок.
- `delete 63\n` — 202, асинхронное удаление.
- `save <id> <байтовая длина имени UTF-8>\n`, затем имя и перевод строки,
  затем прежний формат снимка. ID 64 означает новый набор.

Пример создания (после последних данных перевода строки **нет**):

```text
save 64 6
日本
bus=2 mode=0 hz=20000000 lsb=0 cs_high=0 format=hex
lengths=5,2,0,5
9F 00AA01 02
```

Длины четырёх текстов задают границы их конкатенации. Сервер проверяет UTF-8,
имя, уникальность, параметры SPI и команды перед началом записи.
202 означает принятие операции. Завершение: `GET /api/commands`,
`busy=false`, `save_ok=true`, `error=0`. Ответ также содержит `id`, `name`,
`scanning`, `scan`, состояние Flash, настройки и `commands`.
Прежний `POST /api/commands` обновляет текущий набор либо создаёт Default в ID 63.
При сетевом обрыве браузер не повторяет запись автоматически.

Браузеры имеют собственные рабочие поля. Запись явно адресуется по ID;
одновременная операция отвергается как busy. Последовательные обновления
одного ID из разных браузеров сохраняют последнюю успешно принятую версию.

## Проверки

ARM-макет: 64 набора и полный каталог, UTF-8/32 символа, дубликаты,
переименование, миграция v1, CRC/резервная копия, прерывание записи и удаления,
повторное использование ID и чужие данные в хвосте сектора. HTTP: фрагментация,
байтовая длина японского имени, однократность выполнения. UI: создание,
выбор/удаление без передачи SPI2, сохранение ручной очереди и имён при смене языка.
Испытания реальной W25Q64JV с отключением питания выполняются отдельно.
