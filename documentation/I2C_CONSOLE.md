# I2C-консоль стенда

Реализована на аппаратном **I2C1 STM32F411**, C99, CMSIS и регистры.
HAL, Arduino и программное формирование SCL не используются.

## Подключение

| Сигнал | Black Pill |
| --- | --- |
| SCL | PB8, AF4, open-drain |
| SDA | PB9, AF4, open-drain |
| GND | Общая земля с устройством |

На SCL/SDA нужны **внешние подтяжки к 3,3 В**. Для коротких соединений начать
с 4,7 кОм, а пригодность 400 кГц проверить по фронтам осциллографом; ёмкость
линий и подтяжки готового модуля учитываются вместе. Внутренние подтяжки
отключены. SPI2 PB12–PB15, Ethernet/Flash SPI1 и RTC/LSE остаются отдельными.
Назначение PB8/PB9 сверено по [ST DS10314, таблица AF](https://www.st.com/resource/en/datasheet/stm32f411ce.pdf).

## Работа в браузере

Кнопки **SPI / I2C** выбирают видимую консоль. Команды, параметры, TX/RX,
имя набора и несохранённые изменения каждой шины сохраняются отдельно в RAM
браузера. Переключение не посылает запрос обмена и не пишет Flash. Во время
принятых передач и операций Flash переключатель временно заблокирован:
ответ относится к той консоли, в которой пользователь нажал «Передать».

Четыре поля команд, HEX/ASCII, автоматические пробелы HEX, жёлтые ошибки,
ручная очередь и окно библиотеки работают как для SPI. I2C-настройки общие
для четырёх команд:

- **Адрес**: два HEX-символа, 7 бит, `08…77`, без сдвига и бита R/W.
  Например, адрес EEPROM `0x50` вводится как `50`, а не `A0/A1`.
- **Запись**: 1…256 байт TX, затем STOP; RX пустой.
- **Чтение**: 1…256 байт RX; поле TX отключено и в запрос не включается.
- **Запись → чтение**: 1…256 байт TX, повторный START, 1…256 байт RX, STOP.
  Подходит для указателя регистра/адреса: для 16-битного указателя набрать
  оба адресных байта в нужном устройству порядке, например `00 10`.
- **Частота**: 100 кГц либо Fast mode до 400 кГц.

APB1 = 16 МГц. Для 100 кГц CCR=80, TRISE=17; для Fast mode с duty=2
CCR=14, TRISE=5, фактическая частота **380952 Гц**. Она не превышает 400 кГц
и показывается в результате. PLL для I2C не переключается. HSI задаёт
номинальную частоту; физическая точность зависит от его погрешности и фронтов.

Пример: адрес `50`, «Запись → чтение», RX=4, TX=`00 10`.
На проводах: START, A0, 00, 10, повторный START, A1, четыре байта, NACK, STOP.
Смысл указателя и готовность устройства после внутренней записи определяются
его протоколом. Прошивка не делит запись на страницы EEPROM и не делает ACK polling.

## API и ошибки

`POST /api/i2c`, заголовок `X-Device-Control: 1`, точный Content-Length.
Порядок полей заголовка тела фиксирован; числовые поля API десятичные:

```text
bus=1 hz=100000 addr=80 op=2 read=4 format=hex
00 10
```

После `10` лишний перевод строки не требуется. `op=0/1/2` означает запись,
чтение, запись/чтение. Чистое чтение имеет пустое тело после первой строки;
для записи `read=0`. Формат `ascii` передаёт коды 1…127, HEX — полные пары.
Байт адреса I2C формирует MCU, добавлять его к TX не нужно.

Ответ JSON: `bus`, `address`, `operation`, `hz` (фактическая), `requested_hz`,
`count` (число подтверждённых TX-байт), `read_count`, `tx`, `rx`,
`transfer_us`, `error`. Адресные байты не входят в TX/RX и счётчики.
Время измеряется DWT от START до завершения STOP. HTTP-ошибка тоже возвращает
JSON с доступной частью TX/RX; доставка HTTP-ответа не повторяет обмен.

| error | Смысл |
| --- | --- |
| 0 | Успех, HTTP 200 |
| 1 | NACK адреса или данных, HTTP 409 |
| 2 | BUSY или SCL/SDA удерживаются LOW, HTTP 409 |
| 3 | Общий тайм-аут 100 мс, HTTP 504 |
| 4 | Ошибка шины/OVR, HTTP 409 |
| 5 | Потеря арбитража, HTTP 409 |
| 6 | Недопустимая команда, HTTP 400; периферия не запускается |

Все ожидания ограничены общим тайм-аутом, дополнительная попытка завершения
аварийного STOP — не более 2 мс. При потере арбитража STOP не генерируется.
Нет автоматических повторов команды, сканирования адресов и импульсов
«восстановления» SCL. При ошибке устройство могло принять часть записи;
повторять её следует по смыслу протокола. Без подключённого ведомого с
подтяжками ожидается NACK; без подтяжек возможен BUSY из-за LOW на линиях.

Один запрос выполняется целиком в основном цикле. Разные HTTP-клиенты
обслуживаются последовательно на физической шине; при растягивании SCL
сетевое обслуживание может задержаться до общего тайм-аута.
Обработка последних 1/2/3 байт использует ACK/POS/BTF и короткие критические
участки, без отключения прерываний на всё время ожидания.

## Память и совместимость

У I2C свой банк на 64 набора: 0x700000…0x77FFFF. SPI имеет отдельные
64 места в 0x780000…0x7FFFFF. Списки независимы, одинаковые имена разрешены
между банками. Старые I2C-наборы переносятся из прежней общей области
сначала проверенным копированием, затем записью удаления в старую пару.
Загрузка набора выбирает нужную консоль и не запускает обмен. Формат v3
добавляет bus, address, operation, read_size к прежней записи v2; размер —
3284 байта, размещение и две копии в секторах прежние. v1/v2 читаются как SPI,
миграция — только при явном сохранении. Четыре пустых поля допустимы для
чистого чтения; при записи пустое поле считается неиспользуемым.
Подробнее: [библиотека](COMMAND_LIBRARY_DESIGN.md).

## Проверки

Регистровая модель выполняет настоящий ARM-код: GPIO AF4/open-drain,
чтение 1/2/3/4/16/256 байт, ACK/POS/STOP, два START без промежуточного STOP,
NACK, BUSY/LOW, тайм-аут, BERR, арбитраж и неизменность SPI1/SPI2.
Также проверены строгий парсер, границы, фрагментированный HTTP, однократность,
библиотека v3 и чтение v1/v2, переключение UI и отдельные черновики.
Это программные проверки; фронты, тактирование, clock stretching реального
устройства и обмен на плате нужно проверить осциллографом/анализатором.

Описание периферии: [ST RM0383](https://www.st.com/resource/en/reference_manual/rm0383-stm32f411xce-advanced-armbased-32bit-mcus-stmicroelectronics.pdf).
